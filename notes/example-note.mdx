This is an example to change the github action v1.2.2 note demonstrating the canonical MDX format for technical writing in the portfolio.

## Writing Technical Notes

Notes should focus on engineering lessons, architectural decisions, and production invariants rather than generic summaries.

### Code and Formatting

Fenced code blocks are supported natively with syntax highlighting:

```typescript
export interface ServiceConfig {
  retries: number;
  timeoutMs: number;
  backoffFactor: number;
}
```

### Key Principles

- Keep the source of truth immutable.
- Prefer explicit state transitions over ambient context.
- Use idempotency keys on write endpoints.
